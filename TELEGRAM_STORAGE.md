# Telegram-backed protected media for NITIN ANIMES

This integration keeps your original video library and encrypted DASH media segments in a private Telegram channel. The website never receives the Telegram bot token or Telegram file IDs. It receives only an authenticated URL to the Supabase Edge Function.

## Important limitations

- This is a **Telegram storage proxy**, not a Widevine license server. Real Widevine playback still requires an authorized Widevine provider and correctly packaged/encrypted content.
- Do not put raw MP4 URLs in the protected player. Upload encrypted DASH initialization/media segments to Telegram and store the DASH manifest in Supabase metadata.
- Telegram's hosted Bot API limits downloads through `getFile` to 20 MB per file. Keep each encrypted segment below 20 MB; target 15 MB or less. The proxy rejects larger segments.
- Every segment is fetched through an Edge Function. This is suitable for a small test, not guaranteed free/high-volume production streaming. Function execution limits, bandwidth, Telegram limits, and latency apply.
- Keep the bot in a **private storage channel** and store `TELEGRAM_BOT_TOKEN` only in Supabase Edge Function secrets. Never put the token or `telegram_file_id` in browser JavaScript, public GitHub files, or a public database view.
- Use this only for videos you own or are licensed to distribute.

## 1. Apply the storage schema

Run `supabase/telegram-storage-schema.sql` in the Supabase SQL Editor after `supabase/schema.sql`. The table has RLS enabled and grants no read access to browser roles. The Edge Function uses a server-only Supabase service key to read file IDs.

## 2. Configure Edge Function secrets

In Supabase Dashboard → Edge Functions → Secrets, set:

- `SUPABASE_URL`
- `SUPABASE_ANON_KEY`
- `SUPABASE_SERVICE_ROLE_KEY` (server-only)
- `TELEGRAM_BOT_TOKEN` (from BotFather; server-only)
- `NITIN_SITE_ORIGIN` (your exact HTTPS Netlify site origin, e.g. `https://your-site.netlify.app`)

Do not commit any of these values. Add the bot to the private channel with permission to access the uploaded files.

Deploy:

```sh
supabase functions deploy telegram-media
supabase functions deploy drm-license-auth
```

The DRM authorization function remains a separate provider adapter and denies licenses until your chosen Widevine provider is integrated.

## 3. Add media assets

The admin page is not yet an uploader for Telegram media. For the initial integration, upload each encrypted initialization/media segment as a document to your private Telegram channel, then record its Telegram `file_id` in Supabase. Do not store the bot token in the database.

Each episode needs:
1. A `manifest` row with `asset_key='manifest.mpd'` and the complete encrypted DASH MPD in `manifest_text`.
2. One `segment` row per initialization/media file. Use unique safe `asset_key` values such as `video/init.mp4`, `video/seg-0001.m4s`, `audio/init.mp4`, or `audio/seg-0001.m4s`; store its Telegram `file_id` and correct MIME type.
3. In the MPD, reference each file with `telegram-asset://video/init.mp4` and matching asset keys for every segment. The proxy rewrites these markers to authenticated Edge Function URLs.

The manifest asset ID becomes its URL:

```
https://YOUR_PROJECT_ID.supabase.co/functions/v1/telegram-media/MANIFEST_ASSET_UUID/manifest.mpd
```

Put that HTTPS URL in the episode's `video_url` field. The player attaches the signed-in user's Supabase access token to requests for this endpoint. The endpoint returns media only for published episodes and never returns Telegram file IDs.

For a test, upload a small encrypted segment to your private Telegram channel and obtain its `file_id` through your trusted bot/backend. Example segment registration (replace every placeholder):

```sql
insert into public.telegram_media_assets
  (episode_id, asset_key, asset_role, telegram_file_id, mime_type)
values
  ('YOUR_EPISODE_UUID', 'video/init.mp4', 'segment',
   'TELEGRAM_FILE_ID_FROM_YOUR_BOT', 'video/mp4');

insert into public.telegram_media_assets
  (episode_id, asset_key, asset_role, manifest_text)
values
  ('YOUR_EPISODE_UUID', 'manifest.mpd', 'manifest',
   '<MPD xmlns="urn:mpeg:dash:schema:mpd:2011" type="static"><!-- replace with your complete DRM-packaged MPD; use telegram-asset://video/init.mp4 and matching asset keys --></MPD>')
returning id;
```

The returned UUID is the `MANIFEST_ASSET_UUID` used in the episode's `video_url`. The short MPD above is only a placeholder and will **not** play; use the complete MPD generated by your DRM packaging workflow, with every init/media segment mapped to an asset key. Never use a clear/raw video as the DRM test asset.

## 4. Package and test

Use a DRM packaging tool and your Widevine provider's supported key/packaging workflow to produce CENC-encrypted DASH. Keep the manifest's segment URLs mapped to Telegram asset keys. Test with a short video you own. Playback will not work until encrypted segments, the matching MPD, Telegram asset rows, configured Supabase, and an authorized Widevine license provider are all in place.

## 5. Security and cost notes

The endpoint authenticates every request, checks that the episode and anime are published, resolves only asset keys attached to the same episode, and keeps the Telegram token and file IDs server-side. It does not make a raw Telegram URL public. It cannot prevent screen recording or every form of copying.

This free-first architecture has no guaranteed zero-cost production bandwidth. For a busy site, use a suitable object store/CDN for encrypted segments and a production DRM service; Telegram can remain an archive if your rights and Telegram's terms permit it.
